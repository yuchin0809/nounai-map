## 3. 他人の投稿への引用・返信で露出を得る方法とリスク

### 事実([確認]。既存調査 `research_non_viral_and_mechanics.md` の公開コード由来)

- 公開された既定の重みでは、リプライ(5.0)・引用(5.0)は、いいね(0.66)より大きい。ただし本番値は非公開部分がある。
- ネガティブな反応(興味なし -52.272、ミュート -58.8、ブロック -31.2、通報 -234.0)が大きく減点される。
- 「フォロー外への配信は割引される」という記述があり、係数は非公開。
- 検索で、Xが「攻撃的で不快な可能性がある返信を検知して表示しない仕組み」を作ってきたという説明が出てきたが、出典の特定ができていない。営業的な返信が同じ扱いになるかは**不明**。

### 見つからなかったもの

- **[未発見]** 「無名アカウントが他人の投稿に価値のある返信をして、フォロワーやプレイ数を得た」ことを数字で示した資料。日本語でも英語でも見つかりませんでした。

### 現実的な方法([推測])

1. **自分の作品と同じテーマの投稿に、本当に役立つ・面白い返信をする。** たとえば地理・県民性・地図・方言の投稿に、事実の補足や、小さな面白い発見を返信する。作品の宣伝は書かない。プロフィールを見た人が自然に興味を持つ導線(プロフィールの固定投稿とURL)だけ整えておく。
2. **返信は、元の投稿から短い時間のうちに。** 古い投稿への返信は見られにくい(推測)。なお、48時間より古い投稿は推薦から外れる(確認)。
3. **「自分の作品のURLを貼る」「毎回同じ文面」は避ける。** 同じ内容を繰り返すと、ミュート・ブロック・通報につながり得る(重みは上記)。
4. **引用は、元の投稿者の意図を尊重する。** 揶揄や、相手を下げる引用は避ける。
5. **目安は少なく、質を重視。** 1日に数件までの具体的な根拠はありません(推測)。

### リスク

- ミュート、ブロック、通報(上記の大きな減点)。
- スパム扱い。Xの規約は取得できなかったため、内容は未確認です。自分で規約の「プラットフォーム操作とスパム」を読んでください。
- 高校生の個人情報(学校名、顔、居住地)を出さないこと。大きなアカウントに絡むことで炎上に巻き込まれる可能性もある。
- 効果が測りにくく、時間を取られる割に結果が出ない可能性が高い(推測)。

### 「脳内日本地図」に当てはめた案(すべて[推測])

現状のコード(`js/app.js`)は、結果をシェア画像にして、`navigator.share` またはXの投稿画面(intent URL)に渡す作りです。足りないのは、**見た人が自分も同じ条件で試したくなる導線**です。

1. **同じ問題で勝負するURL(挑戦状)。**
   - 10県チャレンジの県の組み合わせを、乱数の種(シード)としてURLに入れる(例: `?s=48271&score=62`)。URLを開いた人は同じ10県で遊び、最後に「相手の点数」と比較できる。
   - GitHub Pagesだけで実装できる(サーバー不要)。URLのパラメータをJavaScriptで読むだけ。
   - 共有文: 「同じ10県で勝負しよう。私は62点。抜ける?」
   - 注意: URLを書き換えれば点数は偽装できる。ランキングにはせず、友達同士の遊びに留める。
2. **日替わりの10県(全員同じ問題)。**
   - 日付から種を作れば、サーバー不要で「今日の10県」になる。Wordle型の「皆が同じ問題」を作れる。
   - 結果文に日付と点数を入れる。みんなの分布は集計できない(サーバーがないため)。
3. **結果の一行コピー。** 画像が使えない場面(LINE、Discord)のために、「#脳内日本地図 2026-10-18 10県 62点『県境がバグってる人』」のようなテキストをコピーするボタン。
4. **ご当地の挑戦。** 「自分の県だけ最初から置いてある」「北海道だけ当てる」などのモードは、地元ネタで語りたくなる(既存調査の「うちの町が出た」と同じ考え方)。
5. **OGP(リンク先のプレビュー画像)の限界。** GitHub Pagesは静的配信なので、URLの結果ごとにプレビュー画像は変えられない。結果画像は、ユーザーが画像として貼る前提にする(現状の設計は正しい)。XがOGPをキャッシュする点にも注意(Zenn記事: https://zenn.dev/mgmg_life9/articles/5f73e742651c2a)。
6. **コメントの誘導。** 結果画像に「ズレた県ワースト」を入れる(「福岡を北海道の横に置いた」など)と、突っ込みたくなる。リプライは重みが大きい(確認済みの既定値)ため、語りたくなる要素は意味がある。
7. **UGC(ユーザーが作る要素)** は、GitHub Pagesだけだとモデレーションを自分たちで持てないため、保存や公開の機能は作らない方が安全(既存調査でも荒らしと運用負荷が指摘されている)。

## 5. 同じ作品を数回に分けて再投稿する運用

### 見つかったこと

- [確認] Xの公開コードには、**同じ著者の2本目以降は減衰する**(著者多様性)、**48時間より古い投稿は除外される**、という記述がある(既存調査)。つまり、同じ日の連投は2本目以降が不利になり、2日以上あけた投稿は別々の評価の機会を持つ、と読める。
- [報告] 第三者の解説(Circleboom、socialkit など。検索結果の要約)は、再投稿する場合は**フックを変える・数字を更新する・切り口を変える**ことを勧め、ほぼ同じ内容を短期間に繰り返すと表示が落ちたり、ポリシー上のフラグが立つことがある、としている。ただしこれは**Xの公式基準ではありません**。
- [報告] 「同じ投稿のリポストは一度に1件しか存在できない」「自動リポストは12時間後に取り消される」という解説があった(第三者)。自動リポストのツールは、効果が不確かで規約上のリスクもあるため、使わない方がよい[推測]。
- [報告] 漫画家の例として「宣伝は最低6回しないとフォロワーに行き渡らない」という助言があった。これは**フォロワーがいる人の話**で、0人の今回には当てはまらない[推測]。
- **[未発見]** 「同じ無名のゲームを複数回に分けて投稿して伸びた」ことを、数字つきで書いた資料。性癖俳句も、投稿の頻度や再投稿の計画は書かれていませんでした。

### 伸びた型(再投稿というより「別の切り口の投稿」として)

- 流行の型に乗る: 15秒トレーラー、1 year in 1 minute、「My game is good, the algorithm just ignores me」など。通常の告知より便乗投稿の方が、2〜4倍の反応があった例がある(既存調査の AUTOMATON の数字。ただし記事は「ミームは最後の一押しの可能性」と慎重)。
- 同じゲームでも、**毎回違う「入口」**にする。

### 避けるべき運用

- 同じ日に何本も投稿する(2本目以降は減衰)。
- 投稿を消して、同じ内容を再投稿する(既存の `promo/POSTING_PLAN.md` でも禁止している)。
- 文面と動画が同じものを、短い間隔で繰り返す。
- 自動リポスト、外部ツールで水増しする。
- 他人の投稿に宣伝リプを連投する。

### 提案する運用(推測)

| 日 | 投稿 | 狙い |
|---|---|---|
| 0(済) | 主投稿(動画、リンクなし)+返信にリンク | 結果: 84imp / 3クリック |

## 6. 今回の数字(84 → 24 → 3)から言えること、言えないこと

### 計算(割り算のみ。事実)

- 返信のimp / 主投稿のimp = 24 / 84 = 約29%
- クリック / 主投稿imp = 3 / 84 = 約3.6%
- クリック / 返信imp = 3 / 24 = 12.5%。n=24 なので、95%信頼区間(Wilson)はおよそ **4%〜31%** と非常に広い。
- 仮にこの比率が変わらないとしても、リンククリック100件には主投稿が約2,800impほど必要、という計算になる(3.6%のまま変わらないという強い仮定を置いた単純計算)。

### 言えること

- [報告] 既存調査によると、非Premiumアカウントの1投稿は通常100imp未満が典型(Buffer)。**84impは、フォロワー0人の無料アカウントとして、特別に悪い数字とは言えません。**
- 今回のボトルネックは、**投稿を見る人の数(上流)**です。見た人のうち3人がクリックしている(下流は動いている)ので、「リンクが機能していない」とは言えません。
- 返信(リンク入り)の24impは、主投稿の約3割の人が、スレッドを開いたか、表示されたことを示します。ただし、**クリックの12.5%が高いか低いかは、n=24では判断できません。**
- 動画つき・リンクなしの主投稿が84imp、リンクが入った返信が24imp、という構造は、「主投稿にリンクを入れない」という既存の方針が**少なくとも壊滅的ではなかった**ことと矛盾しません。

### 言えないこと

- 「リンクを返信に置いたから伸びなかった」(または「伸びた」)。比較対象(リンクを主投稿に置いた場合)がなく、n=1です。
- 「動画のフックが弱かった」。動画の再生数、再生完了率、プロフィールクリックなどの数字がないため、判断できません。
- 「文面が悪かった」。同上。
- 「クリックした3人が誰か」。自分たち・友達が含まれているかもしれません。
- 「クリックした3人が実際に遊んだか」。GitHub Pagesだけでは分かりません(アクセス解析がない)。
- 「Xに向いていない作品だ」。1回の投稿では結論が出ません。

### 次に確認する数字(Xの分析画面で見られる範囲)

1. 主投稿の**動画再生数**、再生完了率(見られる場合)。
2. **プロフィールクリック数**(リンクをプロフィールに置いているため)。
3. 主投稿と返信の、いいね・返信・リポスト・ブックマークの数。
4. そのimpの何割が「フォロワー外」かは、Xの分析では分かりにくい。分からなければ、それを前提にする。

## 7. 投稿文・動画の改善案(今回の数字に基づく。すべて[推測]、検証は次の投稿で)

今回の数字から言えるのは「上流(見られる数)が小さい」だけなので、**一度に多くを変えず、1回の投稿で1つずつ変えて比べる**のが筋です。

### 現状の投稿文の観察

- 「日本地図、記憶だけで置ける?🗾 ... 何点出る?」は問いで終わっていて、方向は合っています。
- 動画は**台本どおりに自動操作して録画したもの**(`promo/POSTING_PLAN.md` に明記)。実際に遊んだ人の画面の方が、リアルで安心感があると考えられる。
- 主投稿に「無料ゲームを作りました」という**宣伝の言葉**が入っている。冒頭に宣伝があると、スクロールで流れやすい可能性がある。

### 改善案

1. **次の動画は、友達が実際に遊んだ画面を録る。** 「うちの兄は北海道を九州の下に置いた」のような、人の失敗が見える方が語りたくなる。顔や学校名は映さない。
2. **冒頭1〜2秒に、いちばん笑える/ズレた瞬間を出す。** 今の動画は「白紙の地図」から始まる。答え合わせの「県が飛んでいく」所を先頭に出し、そこから「何があった?」と巻き戻す構成にすると、冒頭で止まりやすい可能性がある。
3. **投稿文を「結果の一行」から始める。** 例: 「友達に日本地図を記憶だけで作らせたら、福岡が北海道に引っ越した」。「作りました」は2行目以降へ。
4. **問いを具体的にする。** 「何点出る?」より「あなたが一番ズレる県はどこ?」の方が、返信(自分の県の話)を呼びやすい。返信は、公開コードの既定値で重みが大きい。
5. **返信のリンク文はそのまま維持。** 返信は「遊べます」だけにして、短くする。12.5%のクリック率(n=24)を、まず壊さない。
6. **プロフィールの固定投稿とリンクを整える。** 他人の投稿への返信から来た人が、プロフィールに来てすぐ遊べるようにする。
7. **同じ動画を、Shorts / TikTok にも出す。** 縦の15秒以内。字幕は入れる。プロフィールにURLを置く。Xとは別の発見経路を作るだけで、新しい作業はほぼない。
8. **結果画像の1行目に、挑戦状URLを入れる**(第4節)。見た人が友達に送れる。
9. **URLをチャネルごとに分ける**(`?from=`)。次に何が効いたか分かるようにする。

### 次の投稿の実験設計(例)

- 投稿Aと投稿Bは、2日以上あける。どちらも動画つき・リンクは返信。
- A: 友達の失敗の動画、文面は結果の一行から。
- B: 答え合わせの3秒の動画、文面は具体的な問い。
- 比べる数字: imp、動画再生、返信数、プロフィールクリック、`?from=` 別のアクセス。
- n=1なので、差があっても**傾向の目安**でしかない。複数回やって、はじめて分かること。
